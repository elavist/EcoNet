# ✅ Исправление ошибки размера входного изображения для ONNX моделей

## ❌ Проблема

```
ERROR:obelisk.core.model_engine:Ошибка детекции моделью primary: Error in execution: Got invalid dimensions for input: images for the following indices
 index: 2 Got: 640 Expected: 416
 index: 3 Got: 640 Expected: 416
 Please fix either the inputs/outputs or the model.
```

**Причина:**
- ONNX модель была экспортирована с фиксированным размером входа **416x416**
- В конфиге был установлен `input_size: 640`
- ONNX модели не могут принимать разные размеры входа (в отличие от PT моделей)

## ✅ Решение

### 1. **Определение типа модели при загрузке**

Добавлено сохранение информации о типе модели (ONNX или PT):

```python
# В __init__:
self.model_is_onnx = {}  # Флаг ONNX модели для каждой модели

# При загрузке модели:
self.model_is_onnx[model_name] = onnx_path.exists()
```

### 2. **Автоматическое определение размера входа**

В `_single_model_detect()`:

```python
# Проверяем тип модели
model_is_onnx = self.model_is_onnx.get(model_name, False)

if model_is_onnx:
    # Для ONNX используем фиксированный размер 416
    input_size = 416
    logger.debug(f"⚠️ ONNX модель '{model_name}' - используется фиксированный размер: {input_size}")
else:
    # Для PT модели используем размер из конфига
    input_size = config_input_size
    logger.debug(f"✅ PT модель '{model_name}' - используется размер из конфига: {input_size}")
```

### 3. **Обновление конфига**

`config/config.yaml`:
```yaml
model:
  input_size: 416  # Размер для ONNX моделей (фиксированный), для PT моделей можно увеличить до 640
```

## 📊 Изменения

### `obelisk/core/model_engine.py`:

1. **Добавлен словарь `model_is_onnx`**:
   - Инициализируется в `__init__`
   - Заполняется при загрузке моделей
   - Используется в `_single_model_detect()` для определения размера

2. **Логика определения размера**:
   - ONNX модели → `input_size = 416` (фиксированный)
   - PT модели → `input_size` из конфига (можно увеличить до 640)

### `config/config.yaml`:

- `input_size`: 640 → 416 (для совместимости с ONNX)

## 🎯 Результат

- ✅ ONNX модели работают с размером 416 (как при экспорте)
- ✅ PT модели могут использовать больший размер из конфига
- ✅ Автоматическое определение типа модели
- ✅ Максимальное количество детекций сохраняется (через низкий confidence=0.2 и max_detections=300)

## ⚠️ Важно

- **ONNX модели** имеют фиксированный размер входа (обычно 416)
- **PT модели** могут принимать разные размеры (можно увеличить до 640)
- При экспорте ONNX модели нужно указать размер, который будет использоваться
- Если нужно больше детекций, можно:
  1. Использовать PT модель вместо ONNX
  2. Понизить `confidence_threshold` (уже установлен в 0.2)
  3. Увеличить `max_detections` (уже установлен в 300)

**Проблема исправлена!** ✅
