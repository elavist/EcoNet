## 🎯 Обзор проекта

**ЭКОНЕТ (EcoNet)** - это автономная интеллектуальная система роя роботов для очистки территорий от мусора. Система разработана как **самообучающаяся ИИ-платформа** с возможностью детекции, координации роя роботов и управления через современный графический интерфейс.

### Основная идея
Создание **автономной системы роя**, которая:
- **Видит** мусор через YOLO детекцию
- **Координирует** множество роботов-сборщиков
- **Учится** на собственных данных (активное обучение)
- **Управляется** через современный Material Design интерфейс

### Целевое применение
- Очистка территорий от окурков сигарет
- Сбор мелкого мусора в парках и общественных местах
- Координация роя автономных роботов-сборщиков
- Создание обучающейся системы для различных типов мусора

### 2. Нейронная архитектура (3 нейрона)

Система использует **3 специализированных нейрона** для оптимальной синхронизации:

#### YOLO-Нейрон
- **Роль**: Визуальное восприятие системы
- **Функции**:
  - Обработка кадров через ModelEngine
  - Детекция объектов (мусор, окурки)
  - Отправка детекций через нейронную сеть
  - Хранение буфера последних детекций
- **Соединения**:
  - → Information Hub (синхронизация детекций)
  - ↔ Coordinator (управление детекцией)

#### Coordinator-Нейрон
- **Роль**: Координация задач и распределение между роботами
- **Функции**:
  - Создание и управление задачами
  - Координация между компонентами
  - Мониторинг статусов задач
  - Управление детекцией по командам
- **Соединения**:
  - → Information Hub (синхронизация задач)
  - ↔ YOLO-нейрон (управление детекцией)

#### Information Hub (Хаб Информации)
- **Роль**: Центральный узел синхронизации
- **Функции**:
  - Сбор информации от всех узлов
  - Синхронизация данных между компонентами
  - Хранение истории всех операций
  - Распределение информации между узлами
- **Соединения**:
  - ↔ Все нейроны (двусторонняя связь)

**Примечание**: DeepSeek-нейрон был удален для оптимизации производительности на данном этапе разработки.

## 🧩 Реализованные компоненты

### Core (Ядро системы)

#### 1. UnifiedEngine (`obelisk/core/unified_engine.py`)
- **Назначение**: Универсальный движок координации всех компонентов
- **Функции**:
  - Инициализация и управление всеми сервисами
  - Обработка кадров (детекция + визуальный анализ)
  - Координация роя роботов
  - Управление состоянием системы
  - Статистика и мониторинг
- **Особенности**:
  - Асинхронная архитектура (asyncio)
  - Кэширование детекций
  - Многопоточная обработка (ThreadPoolExecutor)
  - Нейронная сеть коммуникаций

#### 2. ModelEngine (`obelisk/core/model_engine.py`)
- **Назначение**: Управление YOLO моделями
- **Функции**:
  - Загрузка и управление ансамблем моделей
  - Детекция объектов на кадрах
  - Три метода объединения детекций:
    - **Weighted Voting** - взвешенное голосование
    - **Majority Voting** - голосование большинством
    - **Average Voting** - усреднение
  - Оптимизация производительности (ONNX, GPU, FP16, batching)
  - Приоритет PT моделей над ONNX для гибкости размера
- **Особенности**:
  - Поддержка ансамбля моделей
  - IoU-based группировка детекций
  - Динамические веса моделей
  - Автоматическое определение типа модели (PT/ONNX)

#### 3. ModelTesting (`obelisk/core/model_testing.py`)
- **Назначение**: Тестирование моделей при запуске
- **Функции**:
  - Проверка готовности моделей к работе
  - Тестирование с разными параметрами confidence
  - Верификация функциональности
- **Использование**: Автоматическая проверка при старте системы

#### 4. ObjectTracker (`obelisk/core/object_tracker.py`)
- **Назначение**: Отслеживание объектов между кадрами
- **Функции**:
  - IoU-based tracking (IoU >86%)
  - Предсказание позиции объектов (линейная экстраполяция)
  - Удаление старых треков (max_missed_frames)
  - Оптимизация детекций (избегание повторной детекции)
- **Параметры**:
  - `iou_threshold`: 0.86 (высокий порог для точного отслеживания)
  - `max_missed_frames`: 5 (максимум пропущенных кадров)

#### 5. NeuralNodes (`obelisk/core/neural_nodes.py`)
- **Назначение**: Реализация нейронной архитектуры
- **Функции**:
  - Управление нейронами (YOLO, Coordinator, Information Hub)
  - Коммуникация между нейронами
  - Синхронизация данных

### Services (Сервисы)

#### 1. MediaManager (`obelisk/services/media_manager.py`)
- **Назначение**: Управление медиа файлами
- **Функции**:
  - Импорт медиа файлов (видео, фото)
  - Управление метаданными
  - Хранение детекций (pickle файлы)
  - Предобработка видео (автоматическая обработка YOLO)
  - Управление статусом обработки
- **Структура данных**:
  - `data/media/` - хранилище медиа
  - `data/media/detections/` - сохраненные детекции
  - `data/media/metadata.json` - метаданные файлов

#### 2. CacheManager (`obelisk/services/cache_manager.py`)
- **Назначение**: Управление кэшем системы
- **Функции**:
  - Очистка кэша детекций
  - Очистка кэша датасетов (.cache файлы)
  - Очистка временных файлов (__pycache__, .pyc)
  - Комплексная очистка всех кэшей
- **Использование**: Оптимизация использования дискового пространства

#### 3. ModelSelector (`obelisk/services/model_selector.py`)
- **Назначение**: Выбор моделей из сохраненных версий обучения
- **Функции**:
  - Получение списка доступных моделей
  - Парсинг метрик из results.csv
  - Получение информации о модели (mAP, precision, recall, epochs)
  - Выбор и копирование модели (с резервным копированием)
  - Автоматическое определение типа модели (training/direct/current)
- **Метрики**:
  - mAP@0.5 - средняя точность при IoU=0.5
  - mAP@0.5:0.95 - средняя точность при IoU от 0.5 до 0.95
  - Precision - точность детекций
  - Recall - полнота детекций
  - Epochs - количество эпох обучения

#### 4. AnnotationTool (`obelisk/services/annotation_tool.py`)
- **Назначение**: Инструмент ручной разметки для обучения
- **Функции**:
  - Сохранение аннотаций в формате YOLO
  - Сохранение оригинального и размеченного изображения
  - Автоматическое добавление в датасет для обучения
  - Сохранение с confidence 100% для обучения
- **Формат сохранения**:
  - YOLO формат: `class_id center_x center_y width height` (нормализованные координаты)

#### 5. Trainer (`obelisk/services/trainer.py`)
- **Назначение**: Обучение YOLO моделей
- **Функции**:
  - Обучение моделей на датасете
  - Активное обучение (Active Learning)
  - Деплой моделей на edge устройства
  - Версионирование моделей
  - Сохранение метрик обучения

#### 6. TaskManager (`obelisk/services/task_manager.py`)
- **Назначение**: Координация задач и распределение между роботами
- **Функции**:
  - Создание задач на основе детекций
  - Распределение задач между роботами (алгоритм оценки)
  - Мониторинг выполнения задач
  - Обработка таймаутов
  - Управление приоритетами

#### 7. Database (`obelisk/services/database.py`)
- **Назначение**: База данных системы
- **Функции**:
  - SQLite база данных (MVP)
  - Таблицы: detections, tasks, robots, models
  - CRUD операции для всех сущностей
  - Хранение метрик моделей

#### 8. MQTTClient (`obelisk/services/mqtt_client.py`)
- **Назначение**: Централизованная коммуникация между устройствами
- **Функции**:
  - Подключение к MQTT брокеру
  - Публикация/подписка на топики
  - Асинхронная обработка сообщений
  - Коммуникация с роем роботов

#### 9. ActiveLearner (`obelisk/services/active_learner.py`)
- **Назначение**: Активное обучение модели
- **Функции**:
  - Сбор кадров с низкой уверенностью (confidence 0.3-0.7)
  - Сохранение в Data Lake
  - Разметка и дообучение модели
  - Валидация и деплой при улучшении

#### 10. VisionContext (`obelisk/services/vision_context.py`)
- **Назначение**: Анализ визуального контекста
- **Функции**:
  - Анализ текущего кадра
  - Извлечение информации о детекциях
  - Анализ сцены (освещение, качество)
  - Подготовка контекста для обработки

## 💡 Идеи и концепции

### 1. Нейронная архитектура
**Идея**: Система работает как нейронная сеть, где каждый компонент - это "нейрон" со своими связями.

**Реализация**:
- 3 специализированных нейрона (YOLO, Coordinator, Information Hub)
- Двусторонняя коммуникация между нейронами
- Центральный хаб для синхронизации
- Быстрая реакция на изменения

**Преимущества**:
- Естественная синхронизация компонентов
- Масштабируемость
- Автономность системы

### 2. Предобработка видео
**Идея**: Обработка видео заранее для быстрого воспроизведения результатов.

**Реализация**:
- При импорте видео обрабатывается полностью через YOLO
- Детекции сохраняются в файл (pickle)
- При воспроизведении загружаются сохраненные детекции
- Для живых камер - реальная обработка

**Преимущества**:
- Быстрое воспроизведение (нет нагрузки на инференс)
- Можно анализировать результаты оффлайн
- Экономия ресурсов при многократном просмотре

### 3. Ансамбль моделей
**Идея**: Использование нескольких моделей для повышения точности.

**Реализация**:
- Три метода объединения: Weighted, Majority, Average
- IoU-based группировка детекций
- Динамические веса моделей
- Автоматическое управление ансамблем

**Преимущества**:
- Повышенная точность
- Устойчивость к ошибкам отдельных моделей
- Гибкость в выборе стратегии

### 4. Отслеживание объектов (Object Tracking)
**Идея**: Отслеживание объектов между кадрами для оптимизации.

**Реализация**:
- IoU-based tracking (IoU >86%)
- Линейная экстраполяция для предсказания
- Автоматическое удаление старых треков
- Избегание повторной детекции

**Преимущества**:
- Экономия ресурсов (не нужно детектировать заново)
- Плавное отслеживание объектов
- Оптимизация детекций

### 5. Активное обучение
**Идея**: Система сама выбирает данные для обучения.

**Реализация**:
- Сбор кадров с низкой уверенностью (0.3-0.7)
- Автоматическое сохранение в Data Lake
- Разметка оператором или полуавтоматически
- Дообучение модели при улучшении

**Преимущества**:
- Система учится на собственных ошибках
- Эффективное использование данных
- Постоянное улучшение точности

## 🔧 Технические детали

### Технологический стек

#### Python
- **Версия**: 3.8+
- **Библиотеки**:
  - `ultralytics` - YOLO модели
  - `opencv-python` - обработка видео
  - `customtkinter` - современный GUI
  - `asyncio` - асинхронная обработка
  - `paho-mqtt` - MQTT коммуникация
  - `fastapi` - REST API
  - `sqlalchemy` - база данных
  - `numpy`, `PIL` - обработка изображений

#### Модели ИИ
- **YOLO**: Ultralytics YOLOv8
- **Форматы**: .pt (PyTorch), .onnx (ONNX Runtime)
- **Оптимизации**: GPU (CUDA), FP16, batch processing

#### Коммуникация
- **MQTT**: Mosquitto брокер
- **REST API**: FastAPI
- **WebSocket**: для реального времени (опционально)

#### База данных
- **SQLite**: для MVP (легковесная)
- **PostgreSQL**: опционально для production

### Конфигурация

Основная конфигурация в `config/config.yaml`:
- **model**: параметры моделей (confidence, input_size, iou_threshold)
- **active_learning**: параметры активного обучения
- **object_tracking**: параметры отслеживания (iou_threshold, max_missed_frames)
- **data_lake**: пути к данным
- **mqtt**: настройки MQTT брокера
- **logging**: настройки логирования
