## 📊 Детальная иерархия компонентов

### 1️⃣ ЭКОНЕТ (UnifiedEngine)
**Расположение**: `obelisk/core/unified_engine.py`

**Роль**: Центральный координатор всей системы

**Ответственность**:
- Инициализация всех компонентов
- Оркестрация обработки кадров и сообщений
- Управление жизненным циклом системы
- Синхронизация через NeuralSync

**Зависимости**:
- ModelEngine (YOLO)
- LLM Engine (DeepSeek)
- ChatService
- VisionContext
- Self-Awareness компоненты

---

### 2️⃣ DEEPSEEK (LLM Engine)
**Расположение**: `obelisk/services/llm_integration.py`

**Роль**: Мозг системы - понимание, рассуждение, генерация ответов

**Технология**:
- Ollama (локальный LLM сервер)
- DeepSeek v3.1 (модель)
- Endpoint: `http://localhost:11434`

**Возможности**:
- ✅ Thinking Mode (обдумывание перед ответом)
- ✅ Streaming ответы
- ✅ Контекстное понимание
- ✅ Визуальный анализ

**Инициализация**:
```python
# В UnifiedEngine._init_llm_engine()
llm_engine = OllamaProvider(model="deepseek-v3.1:671b-cloud")
```

**Связь с другими компонентами**:
- ChatService → LLM Engine (запросы на генерацию)
- LLM Engine → ChatService (ответы)

---

### 3️⃣ YOLO (ModelEngine)
**Расположение**: `obelisk/core/model_engine.py`

**Роль**: Глаза системы - детекция окурков в реальном времени

**Технология**:
- Ultralytics YOLO
- Модель: `models/cigarette_detector/best.pt`
- Поддержка ONNX формата

**Возможности**:
- ✅ Детекция окурков на кадре
- ✅ Ансамбль моделей (взвешенное голосование)
- ✅ Параллельная обработка
- ✅ Формат bbox: `[x, y, w, h]`

**Инициализация**:
```python
# В UnifiedEngine._init_model_engine()
model_engine = ModelEngine(config)
```

**Связь с другими компонентами**:
- ModelEngine → VisionContext (детекции для анализа)
- ModelEngine → ChatService (детекции для контекста)

## 🔗 Нейронные связи (NeuralSync)

### Схема коммуникации:

```
ModelEngine (YOLO)
    │
    ├───► VisionContext
    │         │
    │         └───► ChatService
    │
    └───► ChatService
              │
              └───► LLM Engine (DeepSeek)
                        │
                        └───► ChatService (ответ)
```

### Типы связей:

1. **ModelEngine → VisionContext**
   - Тип: `data`
   - Данные: Детекции (`List[Dict]`)
   - Назначение: Анализ визуального контекста

2. **ModelEngine → ChatService**
   - Тип: `data`
   - Данные: Детекции (`List[Dict]`)
   - Назначение: Контекст для ответов

3. **VisionContext → ChatService**
   - Тип: `data`
   - Данные: Визуальный контекст (`Dict`)
   - Назначение: Обогащение ответов визуальной информацией

4. **ChatService → LLM Engine**
   - Тип: `signal`
   - Данные: Запрос с контекстом
   - Назначение: Генерация ответа через DeepSeek

## 🔄 Поток данных

### Обработка кадра видео:

```
1. Видео кадр
   ↓
2. UnifiedEngine.process_frame()
   ↓
3. ModelEngine.detect_frame() [YOLO]
   ├─► Детекции → NeuralSync → VisionContext
   └─► Детекции → NeuralSync → ChatService
   ↓
4. VisionContext.analyze_frame()
   └─► Визуальный контекст → NeuralSync → ChatService
   ↓
5. Результат: {detections, visual_context}
```

### Обработка сообщения:

```
1. Сообщение пользователя
   ↓
2. UnifiedEngine.process_message()
   ↓
3. ChatService.process_message()
   ├─► Классификация намерения
   ├─► Получение визуального контекста (из YOLO детекций)
   └─► Подготовка контекста для LLM
   ↓
4. LLM Engine.generate() [DeepSeek]
   ├─► Thinking Mode (обдумывание)
   └─► Генерация ответа
   ↓
5. Ответ пользователю
```

## 📋 Состояния компонентов

### ComponentState (NeuralSync):

- **INITIALIZING**: Компонент инициализируется
- **READY**: Компонент готов к работе
- **PROCESSING**: Компонент обрабатывает данные
- **ERROR**: Ошибка в компоненте
- **PAUSED**: Компонент на паузе

### Иерархия состояний:

```
ЭкоНет (UnifiedEngine)
  ├─► ModelEngine (YOLO): READY/PROCESSING
  ├─► LLM Engine (DeepSeek): READY/PROCESSING
  ├─► ChatService: READY/PROCESSING
  └─► VisionContext: READY/PROCESSING
```

## 🎯 Ключевые взаимодействия

### 1. ЭкоНет → DeepSeek
**Когда**: Пользователь отправляет сообщение
**Что**: ChatService вызывает LLM Engine для генерации ответа
**Контекст**: Включает детекции от YOLO, визуальный анализ, историю диалога

### 2. ЭкоНет → YOLO
**Когда**: Обработка каждого кадра видео
**Что**: ModelEngine выполняет детекцию окурков
**Результат**: Список детекций с координатами и уверенностью

### 3. YOLO → DeepSeek
**Когда**: DeepSeek нужен визуальный контекст для ответа
**Что**: Детекции от YOLO передаются через VisionContext в ChatService, который использует их как контекст для DeepSeek

## 📝 Резюме иерархии

**ЭКОНЕТ** - главный координатор автономной системы роя для очистки от мусора
  ├─ **DEEPSEEK** - мозг (понимание, рассуждение, принятие решений)
  ├─ **YOLO** - глаза (детекция мусора и окурков)
  ├─ **Coordinator** - координатор (управление роем роботов и распределение задач)
  ├─ **Information Hub** - синхронизация (центральный узел для всех данных)
  ├─ **ChatService** - интегратор (объединяет DeepSeek + YOLO)
  ├─ **VisionContext** - визуальный анализатор
  ├─ **NeuralSync** - нейронная сеть для связи компонентов
  └─ **Рой Роботов** - автономные роботы-сборщики (координация через MQTT)

**Принцип работы**: 
- ЭкоНет использует YOLO для "видения" мусора и окурков
- DeepSeek для "понимания", "рассуждения" и "принятия решений"
- Coordinator координирует рой роботов и распределяет задачи
- Information Hub синхронизирует все данные между компонентами
- Роботы-сборщики автономно выполняют задачи по очистке территории

**Улучшенная математика**:
- **IoU группировка** детекций вместо простого округления координат
- **Динамические веса моделей** на основе исторической производительности
- **Комбинированное взвешивание** (вес модели × уверенность детекции)
- **Многокритериальная оптимизация** выбора робота (расстояние, батарея, загрузка, эффективность)
