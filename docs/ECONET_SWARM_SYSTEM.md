# 🐝 ЭкоНет - Автономная Система Роя для Очистки От Мусора

## Обзор

**ЭкоНет** (EcoNet) - это интеллектуальная автономная система роя роботов для очистки территорий от мусора (особенно окурков сигарет). Система использует современные технологии ИИ для координации множества роботов-сборщиков, обеспечивая эффективную и автономную работу.

## 🧠 Нейронная Архитектура (3 Нейрона)

**Примечание:** DeepSeek-нейрон был удален для оптимизации. Система работает с 3 нейронами.

### 1. YOLO-Нейрон
**Роль**: Визуальное восприятие системы
- **Вход**: Кадры видео с камер
- **Выход**: Детекции объектов (мусор, окурки)
- **Соединения**:
  - → Information Hub (синхронизация детекций)

### 2. Coordinator-нейрон
**Роль**: Координация задач и распределение между роботами
- **Вход**: Детекции от YOLO-нейрона
- **Выход**: Задачи для роботов, назначения
- **Соединения**:
  - → YOLO-нейрон (управление детекцией)
  - → Information Hub (синхронизация задач)

### 3. Information Hub (Хаб Информации)
**Роль**: Центральный узел синхронизации
- **Функции**:
  - Сбор информации от всех нейронов
  - Синхронизация данных между компонентами
  - Хранение истории операций
  - Распределение информации по подпискам

## 🤖 Система Роя Роботов

### Типы роботов

1. **Collector Robot (Робот-сборщик)**
   - Оснащение: Вакуум, манипулятор, навигация
   - Задачи: Сбор обнаруженного мусора
   - Коммуникация: MQTT для координации

2. **Future Robots (Будущие расширения)**
   - Роботы-разведчики для сканирования территории
   - Роботы-транспортировщики для доставки мусора
   - Специализированные роботы для разных типов мусора

### Алгоритм Выбора Робота

Система использует **многокритериальную оптимизацию** для выбора оптимального робота:

```python
# Факторы оценки:
1. Расстояние до задачи (вес: 0.5-0.6)
   - Логарифмическая нормализация
   - Чем ближе, тем лучше

2. Уровень батареи (вес: 0.2-0.25)
   - Квадратичная функция (приоритет высокому заряду)
   - Штраф за низкую батарею (<20%: ×0.1, <50%: ×0.7)

3. Текущая загрузка (вес: 0.05-0.1)
   - Экспоненциальное снижение при увеличении задач

4. Эффективность робота (вес: 0.1-0.15)
   - Историческая производительность
   - Учет успешности выполнения задач

5. Время с последнего обслуживания (вес: 0.0-0.05)
   - Предпочтение недавно обслуживаемым роботам

# Формула:
Score = w1×distance_score + w2×battery_score + w3×load_score + 
        w4×efficiency_score + w5×maintenance_score

# Для срочных задач:
- Увеличенный вес расстоянию (0.6)
- Увеличенный вес эффективности (0.15)
```

### Координация Роя

1. **Обнаружение мусора** → YOLO-нейрон детектирует объекты
2. **Создание задачи** → Coordinator-нейрон создает задачу на основе детекций
3. **Выбор робота** → Алгоритм выбирает оптимального робота
4. **Назначение задачи** → Задача отправляется через MQTT
5. **Выполнение** → Робот выполняет задачу и отчитывается
6. **Синхронизация** → Information Hub обновляет состояние

## 📊 Улучшенная Математика Ансамбля Моделей

### IoU (Intersection over Union) Группировка

Вместо простого округления координат система использует **IoU** для точной группировки перекрывающихся детекций:

```python
IoU = Intersection(bbox1, bbox2) / Union(bbox1, bbox2)

# Группировка детекций с IoU >= threshold (по умолчанию 0.5)
# Обеспечивает правильное объединение детекций от разных моделей
```

### Улучшенное Взвешенное Голосование

1. **Динамические веса моделей**
   ```python
   effective_weight = base_weight × reliability_factor
   
   reliability_factor = 0.8 + (avg_confidence × 0.4)
   # Учитывает историческую производительность модели
   ```

2. **Комбинированный вес при усреднении**
   ```python
   conf_weight = model_weight × detection_confidence
   
   # Взвешенное усреднение:
   weighted_bbox = Σ(bbox[i] × conf_weight) / Σ(conf_weight)
   weighted_conf = Σ(confidence × conf_weight) / Σ(conf_weight)
   ```

3. **Голосование по классам**
   - Каждая модель "голосует" за класс детекции
   - Класс определяется большинством голосов
   - Учитываются веса моделей

### Методы Объединения

1. **Weighted Voting (Взвешенное голосование)**
   - Учитывает веса моделей и уверенность детекций
   - Рекомендуется для моделей разной точности

2. **Majority Voting (Голосование большинством)**
   - Требует согласие минимум N моделей
   - Хорошо для моделей похожей точности

3. **Average Voting (Усреднение)**
   - Простое усреднение всех детекций
   - Подходит для ансамбля однородных моделей

## 🔄 Жизненный Цикл Задачи

```
1. Детекция мусора (YOLO-нейрон)
   ↓
2. Создание задачи (Coordinator-нейрон)
   ↓
3. Выбор оптимального робота (алгоритм оценки)
   ↓
4. Назначение задачи через MQTT
   ↓
5. Робот принимает задачу
   ↓
6. Робот движется к цели
   ↓
7. Робот собирает мусор
   ↓
8. Робот отчитывается о завершении
   ↓
9. Обновление состояния в Information Hub
```

```
robots/{robot_id}/heartbeat       # Периодический heartbeat

# Задачи
robots/{robot_id}/tasks           # Задачи для конкретного робота
obelisk/tasks                     # Все задачи системы

# Детекции
obelisk/detection                 # Детекции от камер/сенсоров
obelisk/detection/{location_id}   # Детекции с определенной локации

# Управление
robots/{robot_id}/commands        # Команды роботу (stop, move, vacuum)
obelisk/system/status             # Общий статус системы
```

## 🎯 Оптимизация для Автономной Работы

### Производительность

- **60+ FPS** обработки видео
- **Параллельная обработка** кадров и задач
- **Кэширование** детекций для снижения нагрузки
- **Пропуск кадров** при необходимости для поддержания FPS

### Надежность

- **Резервирование**: Если один робот недоступен, задача переназначается
- **Мониторинг**: Постоянное отслеживание состояния всех роботов
- **Автоматическое восстановление**: Система автоматически восстанавливается после ошибок
- **Самодиагностика**: Компоненты проверяют свое состояние

### Масштабируемость

- **Горизонтальное масштабирование**: Легко добавлять новых роботов
- **Вертикальное масштабирование**: Можно увеличить мощность обработки
- **Распределенная обработка**: Детекция может выполняться на edge устройствах

```yaml
      enabled: true
```
