# 🧠 Архитектура из 3 Нейронов ЭкоНет

## Обзор

ЭкоНет использует архитектуру из 3 специализированных нейронов, пронизывающих все модели для оптимальной синхронизации и обмена информацией.

**Примечание:** DeepSeek-нейрон был удален для оптимизации. Система работает с 3 нейронами: YOLO, Coordinator и Information Hub.

## Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                    Information Hub                           │
│              (Центральный узел синхронизации)                │
│                                                              │
│  • Собирает информацию от всех узлов                         │
│  • Синхронизирует данные                                     │
│  • Распределяет информацию между узлами                      │
│  • Хранит историю всех операций                              │
└──────────────┬──────────────┬───────────────────────────────┘
               │              │
               ▼              ▼
      ┌──────────┐  ┌──────────────┐
      │ YOLO     │  │ Coordinator  │
      │ Neuron   │  │ Neuron       │
      │          │  │              │
      │ Детекция │  │ Управление   │
      │ объектов │  │ задачами     │
      └────┬─────┘  └──────┬───────┘
           │               │
           └───────────────┘
            Прямые связи
```

## 1. YOLO-Нейрон

**Назначение**: Обработка визуальных данных через YOLO модели

**Соединения**:
- **Входящие**: 
  - Hub → YOLO (управление детекцией)
  - Coordinator → YOLO (команды управления)
- **Исходящие**:
  - YOLO → Hub (детекции для синхронизации)
  - YOLO → DeepSeek (детекции для анализа)

**Функции**:
- Обработка кадров через ModelEngine
- Детекция объектов
- Отправка детекций через нейронную сеть
- Хранение буфера последних детекций

## 2. ~~DeepSeek-Нейрон~~ (УДАЛЕН)

**Статус**: Удален для оптимизации производительности.

**Причина удаления**: LLM и Chat функционал были удалены на данном этапе разработки, так как создавали излишнюю нагрузку без критической необходимости для основной функциональности (детекция и координация роботов).

## 2. Coordinator-Нейрон

**Назначение**: Координация задач и управление системой

**Соединения**:
- **Входящие**:
  - Hub → Coordinator (синхронизированные задачи)
- **Исходящие**:
  - Coordinator → Hub (статусы задач)
  - Coordinator → YOLO (управление детекцией)

**Функции**:
- Создание и управление задачами
- Координация между компонентами
- Мониторинг статусов задач
- Управление детекцией по командам

## 3. Information Hub

**Назначение**: Центральный узел синхронизации и обмена информацией

**Соединения**:
- **Входящие от всех узлов**:
  - YOLO → Hub (детекции)
  - DeepSeek → Hub (ответы, размышления)
  - Coordinator → Hub (задачи, статусы)
- **Исходящие ко всем узлам**:
  - Hub → YOLO (обратная связь)
  - Hub → DeepSeek (синхронизированные данные)
  - Hub → Coordinator (синхронизированные задачи)

**Функции**:
- Сбор информации от всех узлов
- Синхронизация данных
- Хранение истории операций
- Распределение информации между узлами
- Автоматическая обработка входящих данных
- Подписки на типы информации

## Нейронные Связи

### Прямые связи (9 соединений)

1. **YOLO → Hub**: Детекции для синхронизации
2. **DeepSeek → Hub**: Ответы и размышления
3. **Coordinator → Hub**: Задачи и статусы
4. **Hub → YOLO**: Обратная связь и управление
5. **Hub → DeepSeek**: Синхронизированные данные
6. **Hub → Coordinator**: Синхронизированные задачи
7. **YOLO → DeepSeek**: Детекции для анализа
8. **DeepSeek → Coordinator**: Команды управления
9. **Coordinator → YOLO**: Управление детекцией

### Типы связей

- **data**: Передача данных (детекции, ответы)
- **signal**: Сигналы управления (команды, статусы)
- **feedback**: Обратная связь (синхронизация)

## Преимущества Архитектуры

### 1. Синхронизация
Все модели соединены через нейронную сеть, обеспечивая полную синхронизацию состояния системы.

### 2. Масштабируемость
Легко добавлять новые узлы и связи без изменения существующей архитектуры.

### 3. Оптимизация
Хаб информации оптимизирует обмен данными между узлами, избегая избыточных операций.

### 4. Диагностика
Каждый узел отслеживает свою статистику (сообщения, состояние, активность), что упрощает отладку.

### 5. Гибкость
Прямые связи между узлами позволяют быструю обработку критических операций, минуя хаб.

## Использование

### В UnifiedEngine

```python
# Архитектура создается автоматически при инициализации
await unified_engine.initialize()

# Доступ к узлам
yolo_neuron = unified_engine.neural_architecture.yolo_neuron
deepseek_neuron = unified_engine.neural_architecture.deepseek_neuron
coordinator_neuron = unified_engine.neural_architecture.coordinator_neuron
hub_neuron = unified_engine.neural_architecture.hub_neuron

# Обработка кадра через YOLO-нейрон
detections = await yolo_neuron.process_frame(frame)

# Обработка сообщения через DeepSeek-нейрон
response = await deepseek_neuron.process_message(message, context)

# Создание задачи через Coordinator-нейрон
task_id = await coordinator_neuron.create_task(task_data)

# Получение информации из хаба
recent_detections = hub_neuron.get_info("detections", limit=10)
stats = hub_neuron.get_statistics()
```

## Статистика

Каждый узел отслеживает:
- Количество полученных сообщений
- Количество отправленных сообщений
- Последняя активность
- Состояние (READY, PROCESSING, ERROR, etc.)
- Размер буфера данных

## Буферы Данных

- **YOLO-нейрон**: Буфер последних 100 детекций
- **DeepSeek-нейрон**: Буфер последних 200 сообщений, 100 размышлений
- **Coordinator-нейрон**: Буфер последних 200 задач
- **Information Hub**: Хранилище 1000 последних операций, индексы по типам

## Потоки Обработки

### Обработка кадра
1. Кадр → YOLO-нейрон
2. YOLO-нейрон → Детекции → Hub + DeepSeek
3. Hub → Синхронизация → Все узлы
4. DeepSeek → Анализ детекций → Coordinator
5. Coordinator → Управление → YOLO (если нужно)

### Обработка сообщения
1. Сообщение → DeepSeek-нейрон
2. DeepSeek-нейрон → Ответ → Hub + Coordinator
3. Hub → Синхронизация → Все узлы
4. Coordinator → Создание задач (если нужно)

## Многопоточность

Все узлы работают асинхронно:
- YOLO-нейрон обрабатывает кадры в отдельном потоке
- DeepSeek-нейрон обрабатывает сообщения асинхронно
- Coordinator-нейрон управляет задачами параллельно
- Hub синхронизирует данные между потоками

## Безопасность

- Все операции защищены блокировками (locks)
- Буферы имеют ограниченный размер (FIFO)
- Очереди имеют максимальный размер для предотвращения переполнения
- Обработка ошибок на всех уровнях
